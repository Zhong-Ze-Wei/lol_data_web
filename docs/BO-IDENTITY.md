# ScoreGG BO 身份的来源判定

`resolve_bo_identity` 给队名规则和 `normalize_result` 使用同一套来源判定。它只读取原件明确声明的 `match_id`，不从文件路径、结果清单中的 `bo` 序号、选手昵称、KDA、日期或持久关联推算 BO。

优先使用 `max_mvp.match_id` 的正整数声明；只有该字段缺失、为 null/空字符串，或来源块缺失/为 null/空对象/空列表时，才允许使用 `max_beiguo.match_id` 的明确正整数。明确提供的零、负数、布尔值、小数、非 ASCII 数字或非数字标识，以及非空非对象来源块，均属于无效声明，不能换用另一块绕过。主备用均有效但不同也会拒绝。主备用均缺失时仍无明确 BO，不制造身份。

队名选择仍要求声明 BO 与实际赛程行 `matchID`、关联 `series_id` 相同，双方 ID 为正且不同，详情与赛程 ID 集合一致；辅助 ID、额外队伍和名称缺项/重复的原约束保持。纯判定函数不读取原件文件；实际归档 SHA、唯一原行及每 Series 版本绑定继续由历史服务和修复入口验证。

明确提供 `win_teamID` 时，它必须是双方之一；红蓝结果已明确互补 0/1 时，还必须与胜方颜色一致。缺失/null/空字符串不补 ID；未确定的红蓝战果不能被当作已结束单局。正常入库仍依据明确红蓝战果生成胜方名称，已有有限名称修复入口仍保留数据库中的未知胜方。

严格采集保留先检查未确定战果、占位时长的 pending 顺序；允许历史残缺时长归档时，明确胜方矛盾仍拒绝。纯队名判定和最终入库交叉检查均识别现有数值解析器接受的可靠 0/1 胜负标志，不能用 `1.0`、浮点数或 `1e0` 等表示跳过胜方检查；矛盾的缓存不会因此重新入队。

队名 provenance 使用 `policy_version: 2`。`detail.series_id` 为本次采用的 BO，同时记录 `series_id_source`（`max_mvp.match_id` 或 `max_beiguo.match_id`）、`primary_series_id` 和 `auxiliary_series_id`。原始 JSON、原始 MVP/败方字段和 canonical 数据 SHA 不被改写；备用 BO 不能伪装成 MVP。既有 v1 已核验赛程证明仍可按同 BO/双方 ID 重新验证，保留其真实赛程证据；新响应记录本次实际政策和锚点，不自动改写全部旧证明。

有限名称修复入口也区分旧证明中的未知 BO 与明确冲突：v1 `detail.series_id: null` 本身不能被当作不同 BO。在当前详情与赛程已通过 v2、旧名称能由详情对应且身份无冲突时，可只补充证明，保持三表名称、主键和其他字段原值。旧明确不同 BO、旧名称无依据或其他身份冲突仍阻断，不因 null 放宽。

`tests/test_bo_identity.py` 保存上述原始身份字段的最小投影和完整原件 SHA，测试不读取生产库或联网；其规范化测试的指标/十槽来自另一个完整 fixture，不能作为九局真实数值重放的证据。九个样本不代表全部缺 BO 记录的分布，也不等于已完成历史队名修复。本政策需独立部署，避免与此前按 v1 冻结的名称修复计划混用。

此前按 v1 审计的 6713 个名称修复候选另有只读兼容核对：实际详情 SHA 与隔离库证据全部一致，6713 个明确胜方 ID 均属于双方并对应唯一可靠 0/1 胜方，未见缺失、占位、畸形或矛盾。报告保存为 `artifacts/audit-team-winner-identity-20261004.json`；该结果仅证明这 6713 个候选的胜方约束兼容，不推断其他来源记录。

发布前另用九份完整真实详情及其赛程原件验证，108项检查通过：五例以实际备用BO核验身份、名称保持原值，四例继续缺证或拒绝；没有进行任何指标重放、数据库写入、HTTP或模型调用。证据为本机 `artifacts/bo-identity-real-nine-proof-v1.json`，与使用完整人工指标fixture的规范化单元测试分开记录。

生产队名修复后冻结库的6713个明确ID另经v2全量只读兼容验证：实际详情字节SHA、完整data canonical SHA与赛程行canonical SHA均与原v1证明相符，v2逐局保持 `schedule:verified`，名称与冻结库相同，不兼容和来源异常均0；实际使用的锚点仍全部为主MVP。证据为本机 `artifacts/audit-bo-policy-6713-compatibility.json`。这不能证明其他来源都满足新约束。

两个实测边界已加入回归：数值形式0/1在纯判定、入库与历史缓存中一致，旧BO为null只代表未证明，不能当作明确不同的BO阻断同名补证据；已知不同BO、身份冲突及无证据旧名称仍拒绝。完整构建、754个Python与62个前端测试、Ruff和diffcheck通过；独立12项针对性复核通过，无P1/P2阻断。
