# 历史状态读取快照

`GET /api/sync/history` 在读取最近运行和覆盖统计之前，检查 SQLite 驱动是否已有事务；没有时显式执行 `BEGIN`。同一响应的各层状态、逐年失败数、有效结果数、待运行任务及重试证据从同一数据库读取快照取得，后台采集提交不会穿插改变其中一部分。

这修复了已用隔离 WAL 数据库复现的问题：第一次统计读到一个失败阶段，后台把另一个 queued 阶段提交为 failed，稍后的逐年查询却读到两个失败阶段。修复后的当前响应仍完整反映提交前的一个失败，下一次请求反映提交后的两个失败。

接口禁用 ORM 自动 flush，不写数据，不提交或回滚调用方已有的读写事务。正常 HTTP 请求创建的读取事务由 Flask 应用上下文结束时关闭；异常请求同样清理，因此读取快照不会跨正常请求沿用。已有事务则保留其快照和寿命，由调用方负责结束。

事务边界仅用于这个 HTTP 接口。`coverage_report` 的采集 CLI 调用、AI 自有只读事务及其他接口保持既有行为。非 SQLite 连接不执行 SQLite 的 `BEGIN`，沿用数据库原有事务配置；本轮隔离并发验证针对 SQLite WAL，未声称验证真实 MySQL 服务。

运行心跳和调度配置来自独立文件，不属于数据库事务快照。数据库快照一致也不代表全历史已经采集完成；待发布、来源缺项、请求失败和失败耗尽仍保留原有含义。

回归覆盖后台另连接实际提交、同响应总数与逐年数及重试证据一致、下一请求看见新状态、正常和异常请求清理、已有读事务保留、已有未提交写入不被提交或回滚，以及未 flush 的修改不被接口自动写入。测试只使用临时数据库，无上游请求、AI 调用或生产数据库修改。


首页四项全库总览也加入该响应的 `overview_stats`，使用与目录覆盖相同的读取事务。原 `/api/stats` 复用同一简单统计函数并保留旧响应与计数语义，事务边界仍由各调用方负责。新的临时SQLite真实并发回归在两项统计之间插入并提交已核验单局及出场：当前响应仍保持目录1局、全库2局、选手2人、战队2支，下一响应同时更新为2/3/3/3。目录已核验为已关联赛程的子集，不能替代全库核验数；独立文件心跳仍不属于数据库快照。
