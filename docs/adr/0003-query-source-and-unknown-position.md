# 0003：按真实来源和未知位置查询

状态：已在独立分支实现并验证；生产部署由统一发布完成。

## 背景

官网基础元数据可以提供真实选手身份和部分成绩，但不提供可靠位置、完整时长或全部指标。此前查询按位置分组会显示“未知位置”，筛选却只接受五个已知角色；用户也无法区分旧 CSV、官网详情和官网基础元数据。

## 决策

选手出场筛选接受 `position: ["unknown"]`，中文“未知位置”归一为 `unknown`。该条件与现有位置分组使用同一口径：来源位置为 `NULL`，或保存值不属于 `a` 至 `e`。空字符串、未识别值也属于未知；不修正原始值，不按选手姓名或其他比赛推断角色。Faker 的未知角色不会补成中单。已有五个位置的代码、别名和显示保持原义，可以同时选择中单与未知位置。

三个分析对象（选手、战队、比赛）都接受 `source` 字符串列表，精确筛选比赛记录实际来源：

| 值                 | 含义           | 问题示例           |
| ------------------ | -------------- | ------------------ |
| `legacy`           | 旧 CSV 导入    | 只看旧 CSV         |
| `scoregg`          | 官网详情战报   | 只看官网详情来源   |
| `scoregg_metadata` | 官网基础元数据 | 只看官网基础元数据 |

多来源列表取并集；未设置来源条件时保留当前查询范围。来源类型与 `verified_only` 是两个独立条件：来源核验和来源类型均不保证阵容、位置、时长或指标完整，`scoregg` 也不能等同于完整战报。目录、规划提示和结果口径同时说明这一边界。

来源条件只作用于现有的比赛表，选手和战队沿各自单局出场与比赛的关联过滤，不额外关联另一种出场表。未知位置仍只用于选手出场分析；不会为比赛或战队查询增加选手关联。非法来源名或计划字段明确拒绝，模型继续只选择受控计划，不能提交自定义 SQL。

## 验证与边界

隔离 SQLite 样本覆盖 `NULL`、空值、未识别角色、已知中单和两者并集，并验证原始角色未被修改。三种来源与核验条件分别组合，三个分析对象的出场数、不同比赛数及日期覆盖证据保持一致；缺失时长和伤害继续返回未知及零个有效样本，不当作数值零。

模拟模型的实际查询入口验证来源/未知位置条件进入规范上下文，目录与规划提示可见，结果保留完整性说明。不发真实模型请求，不写生产数据，也不调整胜率、分均公式、有效样本门槛或只读执行机制。

单次分析仍最多返回 100 行。用户可按来源、实体、日期继续缩小分析范围，并在现有目录页面浏览明细；本次没有实现无限分页、通用缺指标筛选或自动角色推断。
