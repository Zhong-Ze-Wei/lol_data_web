# 0004：蓝白赛事门户与目录查询

状态：采用。决策日期：2026-10-04。

## 背景

用户认为原界面不直观，要求比较适合电竞数据聚合的多种模板，并在四种可点击 Demo 中明确选择「方法 1」。本次采用 A 方案：蓝白赛事门户。正式页面需要同时服务查比赛、查选手、比较数据和自然语言分析，展示的信息必须来自当前数据库。

## 决策

- 沿用 Vue、现有路由、接口和异步资源机制。共用白色页头、深蓝导航、搜索和紧凑面板；首页主列展示最近比赛与 AI 查询，侧栏提供榜单和常用入口。详情页采用身份侧栏与比赛记录主列，手机按阅读顺序合并为单列。
- 选手、比赛、战队、英雄共用目录组件。搜索、位置、赛事、日期和排序交给后端，在完整查询结果上筛选和排序后分页；URL 保存筛选与分页，浏览器返回时恢复。改变筛选回到第一页，保留每页条数。
- 选手目录支持按已收录出场数、确认的最近比赛日期和名称排序。`latest_match_date` 取该选手所有关联比赛中 `date_source=schedule` 的最大日期，与当前页无关。保留旧 `latest_date` 字段供兼容，它不能作为确认的比赛日期使用。关联不到比赛的旧出场仍计入已收录数。
- 总数查询只统计筛选后的选手姓名，不重复计算日期聚合。日期计算先生成独立的已确认比赛子查询，再按 `match_id` 关联出场；SQLite 中保留这个子查询的 `DISTINCT`，以避免优化器将其展开为按姓名索引逐行读取选手宽表。出场计数与日期聚合分别进行，最终左联接日期，保持缺日期及旧孤立记录可见。这个选择来自同一只读快照中列表与总数查询由约 1.8 秒退化至 10.2 秒的实测，无新增索引或数据库迁移。
- 目录位置按该选手最新已收录出场的原始位置归一化；「未知」包含空值和无法识别的值，不根据选手身份猜位置。这个筛选表示最新记录的字段状态，并不表示该选手整个生涯都没有已知位置。
- 比赛搜索覆盖真实队名、赛事名和明确的数字比赛 ID；搜索中的 `%`、`_` 按字面量处理。赛事和队伍筛选可以与日期组合，不根据队名推断赛区或赛季。
- AI 查询保留流式进度、取消、上下文追问、查询计划与 SQL。结果数据和图表先展示，收录范围与有效样本放在可展开的说明中；未知值与真实零值继续区分。对比分析默认中单位，可切换其他位置；仍按相同样本范围计算百分位，不增加虚构的综合实力评分。

## 取舍

白底、细分隔线和明确表格提高信息密度；深蓝只用于导航、标题和重要操作。采用现有组件与图表，减少新依赖和迁移风险。长表格在容器内横向滚动，手机页面本身保持视口宽度。图库缺失时展示姓名或队名，不添加虚构头像。收录数量、最近日期和队伍历史记录均明确口径，不将当前数据声称为完整生涯或当前阵容。

本次不改变采集事实、比赛颜色证据、指标算法或数据来源校验。历史覆盖仍由独立的采集进度展示，选中模板不等于赛事已经补齐。

## 验证

目录接口回归覆盖完整结果排序、确认赛程日期、未知位置、组合搜索和字面量匹配；前端回归覆盖筛选、分页与返回恢复，并保留 AI 和详情的既有业务检查。发布前运行项目 `npm run build` 和 `npm test`，并在连接真实新接口的预览中检查桌面及手机页面。具体测试结果与发布进程记录保存为独立的时间快照，不在本决策中提前宣称通过。
