# 数据口径与来源异常

`verified=true` 说明公开来源与 LOL 游戏类型已核验，不代表比赛阵容、时长和每项指标完整。`source_incomplete` 保存已识别的来源缺项或异常；完整战报还要求可靠时长、两支战队、十名选手及没有已识别的必要缺项或非法指标。历史目录与公开结果清单仍在补采，当前核验数不能当作全历史覆盖率。

## 分均指标

分均伤害、承伤、经济和补刀统一按每局的已知非负总量×60÷ `Match.game_time` 完整秒数计算，再对有效出场取均值。AI 查询、单条 DTO、选手档案、同位置雷达和月趋势使用同一公式。每项独立返回有效样本数：总出场四局、其中两局的对应总量与时长有效时，该分均指标只有两局样本。

总量缺失或为负、比赛时长缺失或不大于1秒时，该局指标为NULL，既不补0，也不参与均值和有效样本。未被整组缺项规则排除的真实总量0，在时长有效时是有效样本。公式取逐局均值，不使用总量之和除以时长之和；关联只从选手或战队出场指向唯一比赛，不关联两张出场表放大记录。

原件保留完整来源原值，业务行保留有依据的来源分均字段；符合下述整组缺项规则的明确0字段会清为NULL。网站不会直接用已知异常来源分均值替代重算结果。例如：

| 单局原件 | 来源字段示例 | 可核对总量及完整时长 | 重算结果 |
| --- | --- | --- | --- |
| [3260](https://img.scoregg.com/match/result/3260.json) | 分均补刀16140 | 269刀、2682秒 | 约6.02刀/分钟 |
| [4325](https://img.scoregg.com/match/result/4325.json) | 分均伤害1016400 | 16940伤害、3033秒 | 约335.11伤害/分钟 |

分均插眼仍使用来源的整数精度 `wp_m`。现有来源没有可信插眼总量，无法按完整分秒重算；0也不能证明整局没有插眼。参团率、伤害占比、承伤占比范围为0–100；历史模式遇到明确无效值时定点清NULL，保存原值与原因，不能截断为100或被旧值保护逻辑填回。

## 整组来源零值

上游没有统一的missing标志。旧战报可能有可靠胜负和击杀，但十人伤害、经济或补刀整组为0。这里采用跨层矛盾的保守业务判断，不把所有0当成缺失。

判定先要求LOL来源、双方胜负已定、原始十个星位的击杀均为有效整数，且每方五星位击杀之和等于该队汇总，总击杀大于0。满足前提后分别检查：

- 伤害族：十人的伤害与承伤，以及双方伤害汇总，全部是来源明确0。
- 经济族：十人的经济与双方经济汇总，全部是来源明确0。
- 补刀族：经济族已满足条件，并且十人的补刀全部是来源明确0。

只将被判定族内来源明确为0的对应总量、分均和占比字段清为NULL；独立的非零来源字段保留。报告记录资格证据、字段名、原值和原因，状态为 `source_incomplete`。定点清NULL与该局写入处于同一事务，不会被已核验旧值的保护逻辑填回。原始JSON不改。

缺键、NULL、空字符串、坏的未具名槽原件、零击杀或击杀汇总不一致不支持对应族的推断。单人真实0、`wp_m`、等级、塔和龙等不在规则中；补刀全0但经济有效也不排除补刀。九名已知选手仍可用原件十槽统计作判断，但不创建第十个身份。伤害族、经济族与补刀族可以重叠，组数不能相加当作不同比赛数。

正常时长的日更战报遇到这些缺项时保存可靠比赛、双方和选手，近14天每日仍重新获取详情，后续补齐可恢复。严格日更缺时长仍保持待处理，非法数值校验没有放宽。比赛详情说明伤害、经济和补刀缺项；全部伤害为NULL时不生成伤害图，真实0照常展示。

## 时长、日期与部分阵容

ScoreGG 历史详情的 `00:00 / 00:01` 是来源占位，不能作为真实局时长。历史模式遇到缺时长、占位或非法分秒，例如 `33:60`，清空比赛、战队与选手业务行的时长并保留原件和原因。平均时长、最快与最长榜、分均指标排除这些样本；严格日更的非法数值校验仍有效。

日期分析只使用 `Match.date_source=schedule` 的确认赛程。来源更新时间仍作来源档案保存，不用于推断比赛年份、月份、赛季或版本；选手明细不能用其旧日期覆盖比赛的确认赛程。

历史战报少一个昵称时，保留可靠比赛、双方与其余已知选手，并移除缺槽中旧记录的猜测身份和战队名单引用。部分阵容按实际人数展示，不因单个昵称缺项丢弃整场，也不创建“未知选手”参与选手统计。只确认公开来源的九人战报仍属于来源缺项，不能算完整十人战报。

昵称恢复只在显式离线校正时使用 `source_identity.py` 的归档索引。星位与来源名单中的选手ID、队伍颜色必须唯一对应；同一 ID 的已知昵称必须没有冲突。候选来自实际来源字段，报告保留对应原件、字段和SHA。重放前再次检查目标及依据原件SHA；重复ID、错误颜色、名称冲突或原件变更均拒绝恢复，不根据数组顺序或别名猜人。
