# 优先补采近期赛事

历史采集仍覆盖整个公开赛事目录，待采赛事改为按来源开始日期由新到旧，未知日期排在最后。这样近期赛事无需等待最早历史全部补完，尚未轮到的旧赛事继续保留在队列。

`history --phase all` 优先处理最新仍有可运行工作的赛事：先采其已发现单局，再展开系列和阶段，最后读取该赛事目录。此赛事暂无可运行工作时进入下一个赛事。同赛事的系列和单局按来源赛程日期由新到旧，未知日期最后；没有可运行赛事目录时，未关联单局也采用同样的日期顺序。日期相同或未知时沿用原 ID 顺序，不根据 ID 猜日期。

`discover` 的赛事、阶段及系列清单，`fetch` 的单局队列采用相同的近期优先原则。只改变待采顺序，不清除成功游标、失败计数、退避期限或终态；耗尽或未到重试时间的任务不会因近期优先而重新入队。已采完整和 `source_incomplete` 单局保持原处理方式，不把缺项当作完整数据。

临时数据库和模拟来源验证近期目录先选、同赛事未完成工作优先、未知日期最后、预算续批不重采成功前缀，以及失败退避和无可运行任务时不自旋。此调度验证不表示近期比赛已经实际补齐；实际来源仍可能尚未发布、失败或缺少字段。
