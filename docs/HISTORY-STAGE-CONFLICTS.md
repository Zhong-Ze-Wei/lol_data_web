# 历史阶段中的跨赛事 BO 冲突

一个阶段响应可能同时包含正常系列与已有另一赛事拥有的 BO。
历史采集先校验完整响应的列表结构、系列日期、重复 BO、比分和原有类型要求。
这些校验失败仍按原策略回滚整个阶段，不提交此前的合法前缀。

只有已存在 `HistorySeries` 且其 `tournament_id` 与当前阶段赛事不同的冲突，
允许按 BO 隔离。冲突系列及其既有比赛、任务、日期、来源证明和归档绑定均不覆盖或重关联。
其余已经通过完整校验的系列按原历史逻辑保存赛程并进入自己的发布/结果清单队列。

来源仍是本次完整阶段列表，不删除冲突原行后制造一份成功响应。
冲突响应归档到阶段目录的 `failed-attempts` 独立文件，合法系列显式绑定该文件的实际 SHA，
保证单局证明可以定位真实唯一原行。阶段以前的成功原件指针保持原值；
首次失败的常规文件入口只创建一次，之后失败不会覆盖其字节。
成功恢复时原常规文件已有不同内容，会使用摘要版本文件，而不是覆盖旧失败原件。

合法系列与阶段的 `failed`、错误、失败次数及退避时间在同一事务提交。
阶段的 `series_count` 仍表示来源中的完整系列数量；运行的失败记录另列
`conflicting_series_ids`、`persisted_series_count`、`source_series_count`、官方来源 URL
和本次完整来源归档的路径与 SHA。即使其他系列已经入库，也不会把阶段标成 `discovered`。
阶段失败只计算一次，不通过抛出已提交的失败再让调用者重复计数。
归档失败或后续原有队列校验错误仍不提交部分系列。

合法的 queued/failed 系列及已知单局任务继续使用原来的独立调度，不要求父阶段成功。
因此父阶段在真实退避中或达到配置的 `max_attempts` 后，这些工作仍可完成。
只有 pending 系列需要刷新阶段；它们仍遵守父阶段退避和耗尽限制，不触发空批次循环。
全部 BO 都冲突时，阶段保持真实失败，不制造合法任务或完成标志。

只有实际后续来源消除冲突且阶段仍具备原重试资格时，才恢复完整 `discovered`，
清除本次失败与退避。不会为了恢复而清空失败次数、提前重试或提高所有阶段的预算。
本功能不修复已存在的单局元数据关联，不推断哪一个赛事拥有冲突 BO，也不修改队名规则。
